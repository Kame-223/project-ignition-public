# ignition-mechanism

「開始の瞬間だけを支援する」個人用アプリ **PROJECT IGNITION** の、**仕組みだけ**を取り出したもの。個人情報・実データ・学校専用の取り込みは入れていない（書き出しのたびに、メールアドレス・名前・パス・科目名・鍵が残っていないかを機械で検査している）。

他のプロジェクトが、部品として持っていけるように置いた。設計の考え方は `ARCHITECTURE.md`。

## 中身

| 部品 | 何をするか |
|---|---|
| `src/tasks_io.py` | JSON の読み書きを、鍵（flock）と原子的な保存で安全に行う。壊れていたら書かずに止める |
| `src/dayplan.py` | 今日の予定を組む（固定予定のすきまに、課題を5分刻みで置く・量の上限・順番の指定・手で置いたものは動かさない） |
| `src/ai_edit.py` | AI が出した「操作の指示」を検査する（書式・値・ユーザーの依頼の言葉・尋ねただけでは動かさない・一度に変える件数の上限） |
| `src/task_note.py` | 課題ごとのノート（Markdown）を正本にする。子タスクのチェックを、アプリと同期する |
| `src/review.py` | 質問の重複・言い換えを同じものとして片付ける（番号が違えば別物） |
| `src/dev_agent.py` / `dev_restart.py` | AI がアプリ自身を直す仕組み。別ブランチ・全テスト・危ない変更は別の AI が審査・ユーザーが「適用」・起動しなければ自動で戻す・OS の隔離 |
| `src/my_events.py` | アプリの中で作る予定の置き場（種類つき・外部カレンダーとの同期の印つき） |
| `src/float_geom.py` | 浮かぶ小窓の「画面の端に触れたら開く」の判定（画面に依存しない計算） |

## 使い方（部品として）
```bash
python3 -m unittest discover -s tests -q   # 汎用部品のテスト（ダミーのデータだけで動く）
```
データの置き場は、各部品の先頭にある `BASE`（既定はこのフォルダ）。人ごとに違う設定（科目・アカウントなど）の項目の例は `config.example.json`（読み込む処理は、使う側で書く）。`dev_agent` / `dev_restart` は、元のアプリの配置（`bin/`・`tests/`・全体画面のサーバー）を前提にした**読むための部品**で、このフォルダだけでは自己改造を完結できない。

## 守っていること
- **罰を持たない**（赤・期限超過・連続記録・点数を出さない）。情報量を絞り、「次の一手」を目立たせる。
- **AI が言ったことと、実際に起きたことを分ける**（実行の結果はアプリが出す。AI が「やった」と言えるのは、実行した後だけ）。
- **本番を直接は直さない**。変更は別の場所で試し、テスト・審査・ユーザーの確認を通ったものだけが本番に入る。いつでも元に戻せる。
- 鍵・実データ・個人の言葉は、この仕組みの外に置く。
